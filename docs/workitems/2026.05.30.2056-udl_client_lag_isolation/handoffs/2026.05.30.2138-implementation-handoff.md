# IMPLEMENTATION HANDOFF

## Goal

Reduce the UDLClient startup cost currently concentrated in `UdlClientControl.PublishClientItems` and especially `PublishClientItems.PostRuntimeUpdateUi`.

The current diagnostic project has 3 folders with one `UdlClient` each, demo mode enabled, one demo module per client, and three SignalWidgets in the first folder. The benchmark still passes, but the P95 budget is nearly exhausted and the visible cost is in the UDL publish path.

## Scope

Included:

1. Instrument and split `UdlClientControl.PublishClientItems.PostRuntimeUpdateUi` into meaningful sub-phases if the current diagnostics are not enough.
2. Identify which operation inside `PostRuntimeUpdateUi` is responsible for the 300-350 ms cost.
3. Make UDL publish/update behavior diff-based and scoped so unchanged runtime structure does not repeat expensive registry or UI work.
4. Preserve current behavior for real runtime structure changes, attach path changes, and visible UI state.
5. Re-run the same `UdlDebug` benchmark with the current 3-SignalWidget setup.

Explicitly not included:

1. Full UDL browser implementation.
2. RealtimeChart changes.
3. Monitor or MonitorView changes.
4. Broad registry architecture rewrites.
5. Demo project expansion beyond the current diagnostic setup.
