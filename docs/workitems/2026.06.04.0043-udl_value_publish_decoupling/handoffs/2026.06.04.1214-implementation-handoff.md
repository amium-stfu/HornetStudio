# IMPLEMENTATION HANDOFF

## Goal
Remove the next confirmed sources of unnecessary per-frame UDL work after the latest throughput retest.

Latest benchmark:

- Scenario: `UdlLoopThroughputRetest-30s`
- `DemoGenerate`: about `155.33/s`, about `7.77 Hz` per module.
- Target: about `200/s`, about `10 Hz` per module.
- `DemoLoopTotal`: `233` loops, about `7.77/s`, `P95=40.2 ms`, `Max=88.9 ms`.
- `UdlSynchronizeBitValues`: `12833`, about `427.75/s`, despite `UdlModuleExposures: []`.
- `RegistryPublish[SteadyState]`: about `773.47/s`.
- `set`, `state`, and `alert` still publish at about `113/s` each.
- `TargetValueRefreshExecuted[SteadyState->SteadyState]`: about `88.10/s`, `P95=98.2 ms`, `Max=373.7 ms`.
- `ChartRenderCount=0`, `BrowserDispatcherPosts=0`.

The immediate goal is to remove unnecessary exposure synchronization when no exposures are configured and reduce unchanged low-value channel churn.

## Scope
- Optimize `UdlClientRegistryProjection.OnRuntimeFrameReceived` and exposure synchronization for empty or unchanged exposure definitions.
- Avoid high-frequency publication for unchanged `set`, `state`, and `alert` values.
- Keep `read` and `out` high-frequency updates intact.
- Preserve real UDL/CAN semantics.
- Preserve whole-module attachments.
- Do not optimize UI rendering or charting.

## Starting Point
- `benchmarks/ui_lag_bench_project/Folders/main/Clients/Udl/udl1.yaml` has `UdlModuleExposures: []`.
- Even with no exposures, `UdlSynchronizeBitValues` runs about `427.75/s`.
- This is likely per-frame overhead with no useful work.
- `set`, `state`, and `alert` are also still published regularly even when their values are often unchanged.

## Tasks
1. Inspect `UdlClientRegistryProjection.OnRuntimeFrameReceived`.
2. Confirm why `SynchronizeBitValues` is called when `UdlModuleExposures` is empty.
3. Cache parsed exposure definitions in `UdlClientRegistryProjection` or equivalent local state.
4. Make `OnRuntimeFrameReceived` return immediately when there are no active bit exposures.
5. Ensure exposure cache refreshes when the UDL definition changes.
6. Inspect `SimulatedHostUdlClient.ApplyModuleSnapshot` and current equality checks.
7. Prevent unchanged `set`, `state`, and `alert` updates from raising source item changes.
8. Keep `read` and `out` updates at the intended telemetry rate.
9. Add focused tests where practical.
10. Build and run a 30s benchmark.
11. Update `docs/workitems/ChatHandoff.md` with final measurements.

- `src/HornetStudio.Editor/UdlClients/UdlClientExposureProjection.cs` -> Add helper only if needed, for example a cheap `HasActiveBitExposures` path or overload accepting parsed definitions.
- `src/HornetStudio.Editor/Widgets/UdlClient/SimulatedHostUdlClient.cs` -> Avoid setting unchanged `set`, `state`, and `alert` values if this is not already enforced by lower layers.
- `src/HornetStudio.Editor/Monitoring/UiResponsivenessDiagnostics.cs` -> Keep existing diagnostics; add no new broad instrumentation unless required.
- `src/HornetStudio.Editor.Tests/Program.cs` or relevant focused tests -> Verify empty exposures skip synchronization and unchanged channels do not emit unnecessary changes.
- `docs/workitems/ChatHandoff.md` -> Update with before/after rates.

## Implementation Order
1. Read `UdlClientRegistryProjection.OnRuntimeFrameReceived`, `UpdateDefinition`, `Refresh`, and `NormalizeDefinition`.
2. Read `UdlClientExposureProjection.ParseDefinitions` call sites and `SynchronizeBitValues`.
3. Add a field in `UdlClientRegistryProjection` that stores whether active bit exposures exist.
4. Refresh that field whenever `_definition` changes.
5. Change `OnRuntimeFrameReceived` to return immediately when no active bit exposures exist.
6. If parsing currently happens repeatedly, store parsed exposure definitions or add a cheap helper to avoid repeated parsing.
7. Read `SimulatedHostUdlClient.ApplyModuleSnapshot` and `SetReadValue`.
8. Change low-value channel writes so unchanged `set`, `state`, and `alert` values do not raise events:
   - `set` should mirror write value only when changed.
   - `state` should update only when state code changes.
   - `alert` should update only when alert text changes.
9. Do not suppress `read` or `out` telemetry updates unless equality proves the numeric value is unchanged.
10. Add focused tests:

    - non-empty active bit exposure still synchronizes.
    - unchanged low-value channels do not raise repeated changes.
