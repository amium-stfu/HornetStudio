# IMPLEMENTATION HANDOFF

## Goal
Close the remaining UDL demo/runtime throughput gap after the first value publish decoupling implementation.

Current retest result:

- `DemoGenerate`: about `149.33/s` total.
- Per module: about `7.47 Hz`.
- Target: about `200/s` total for 20 modules, about `10 Hz` per module.
- `SignalReceive`: about `148.67/s`.
- `TargetValueRefreshExecuted[SteadyState->SteadyState]`: about `110.8/s`, `P95=6.9 ms`, `Max=20.9 ms`.
- `RegistryPublishDuration PropertyUpdated.read`: `P95=12.6 ms`, `Max=90.3 ms`.
- `ChartRenderCount=0`.
- `BrowserDispatcherPosts=0`.
- No fatal `UiFolderContext.Dispose()` exception in the latest run.

The remaining work is to isolate and remove the residual cost inside the UDL runtime/demo update loop and its immediate non-UI side effects.

## Scope
- Measure the remaining cost inside `SimulatedHostUdlClient.SimulationLoopAsync` and adjacent UDL runtime/projection callbacks.
- Keep the first decoupling implementation intact unless measurements prove a regression or unnecessary overhead there.
- Apply only focused fixes that reduce per-module loop cost or avoid redundant per-frame work.
- Preserve whole-module UDL attachments.
- Preserve direct writeback and immediate structural updates.
- Do not optimize Avalonia rendering or charting in this workitem.

## Starting Point
- The broad synchronous public registry fan-out has improved substantially:
  - baseline `DemoGenerate` was about `45/s`.
  - latest retest `DemoGenerate` is about `149/s`.
- The target is still not met.
- Registry publish volume remains high:
  - `RegistryPublish[SteadyState]`: about `775.6/s`.
  - `read`: about `221.8/s`.
  - `out`: about `221.2/s`.
  - `alert`, `state`, `set`: each about `110.9/s`.
- This suggests the remaining limiter may be one or more of:
  - per-module `ApplyModuleSnapshot` setting values/properties that are unchanged.
  - per-module `FrameReceived` callbacks.
  - `UdlClientRegistryProjection.OnRuntimeFrameReceived`.
  - unnecessary `SynchronizeBitValues` or attachment/exposure work.
  - publication of unchanged or low-value `set/state/alert` channels.
  - flush cadence or queue implementation overhead in the decoupling layer.

6. If `ApplyModuleSnapshot` / channel setters dominate:

## Out of Scope
- UI visual redesign.
- Chart optimization.
- Replacing `HostRegistries.Data`.
- Broad `PageItemModel` refactoring.
- One timer per demo module as an architectural workaround.
- Requiring users to reduce UDL attachment breadth.
- Release/versioning work.

## Risks / Watchouts
- Skipping unchanged property sets is safe only if equality comparison preserves expected `ItemModel` change semantics.
- Batching `FrameReceived` may be safe for demo but unsafe for real CAN semantics; keep any batching scoped if necessary.
- Skipping `SynchronizeBitValues` when no exposures exist is likely low-risk and should be considered early.
- `set`, `state`, and `alert` may be lower-frequency in practice; publishing them every tick can waste throughput.
- Reducing public publication volume must not break writeback or structure synchronization.
- Diagnostics themselves can distort the benchmark if they are too detailed.
