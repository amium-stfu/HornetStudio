# IMPLEMENTATION HANDOFF

## Goal
Close the gap between public `read` registry publications and Signal widget receive/update throughput.

Latest benchmark:

- Scenario: `UdlDemoPeriodicScheduler-30s`
- `DemoGenerate`: about `182.65/s`.
- `RegistryPublish[SteadyState]`: about `497.04/s`.
- `RegistryPublish read`: about `249.67/s`.
- `SignalReceive`: about `158.95/s`.
- `TargetValueRefreshExecuted[SteadyState->SteadyState]`: about `117.02/s`, `P95=32.7 ms`, `Max=134.8 ms`.
- `ChartRenderCount=0`.
- `BrowserDispatcherPosts=0`.

The generator and public registry are now close enough that the next bottleneck is likely registry-to-Signal relevance/coalescing/latest-value delivery.

Target behavior:

- `RegistryPublish read` may be above `200/s`.
- Signal widgets should process visible `*.read` targets close to `20 * 10 Hz = 200/s`.
- Coalescing should limit UI work but must not lose the latest value or under-schedule refreshes.

## Scope
- Inspect and measure `HostRegistries.Data.ItemChanged` to `PageItemModel` Signal target update flow.
- Add bounded diagnostics to separate relevant registry events from coalesced/skipped/applied Signal updates.
- Fix pending/latest-value handling only if the measured path shows dropped or under-scheduled updates.
- Preserve current UI coalescing intent and low dispatcher backlog.
- Do not change UDL generation, registry publication, charting, or benchmark YAML in this workitem.

## Starting Point
- Public `read` publication is already higher than the desired visible signal target.
- Signal receive/update count remains lower than target.
- Signal widgets have `RefreshRateMs: 100` in the bench project.
- Coalescing is expected, but it should deliver about `200/s` total for 20 visible widgets at 10 Hz if input is available.

## Risks / Watchouts
- `RegistryPublish read` may include paths not visible as Signal widgets. Verify path overlap before calling events lost.
- `SignalReceive` may currently count actual applied/displayed changes, not raw relevant registry events. Name semantics matter.
- Formatting may hide changes if values round to the same display text; distinguish raw value changes from display text changes.
- Over-aggressive scheduling can reintroduce UI backlog. Keep refresh cadence bounded.
- Pending full refresh must still win over value-only refresh.
