The Browser panel should expose a `Monitor` entry that opens a folder-local monitor browser/editor for `Monitoring/Monitor.yaml`.

## Actual Behavior
The sidebar XAML only declares browser buttons for enhanced signals, custom signals, controllers, and functions. No monitor button or click handler exists.

- Added `Monitor` button and handler to the Browser sidebar.

## Problem
The Monitor rule dialog does not consistently use theme colors and rejects the shown custom rule although the rule is otherwise valid.

## Expected Behavior
The dialog should use the active editor theme for fields/buttons and allow a monitor refresh rate of `100 ms`.

## Actual Behavior
The screenshot shows default/light field colors, and Save is blocked with `Value must be a whole number greater than or equal to 250.` when `Refresh rate (ms)` is `100`.

## Relevant Code
- `src/HornetStudio.Editor/Widgets/Monitor/MonitorEditorDialogWindow.axaml` uses direct style bindings inside `Window.Styles`.
- `src/HornetStudio.Editor/Widgets/Monitor/MonitorEditorDialogWindow.axaml.cs` validates `RefreshRateMsText` with a hard-coded minimum of `250`.
- `src/HornetStudio.Editor/Models/MonitorDefinition.cs` normalizes monitor refresh rates to at least `250`.
- `src/HornetStudio.Editor/Widgets/Monitor/MonitorControl.axaml.cs` clamps the runtime timer interval to at least `250`.

## Attempted Fixes
- Changed Monitor dialog style bindings to use `#Root.DataContext` for dialog-level field/button/token theme values.
- Lowered the monitor refresh minimum consistently from `250 ms` to `100 ms` in dialog validation, definition normalization, and runtime timer interval.
- Added an editor self-test that confirms `100 ms` is accepted.
- Validation: `dotnet build src\HornetStudio.Editor\HornetStudio.Editor.csproj --no-restore` succeeds with 0 warnings and 0 errors.
- Validation: `dotnet build src\HornetStudio.Editor.Tests\HornetStudio.Editor.Tests.csproj --no-restore /p:OutDir=B:\HornetStudio\artifacts\editor-tests\` succeeds with 0 warnings and 0 errors.
