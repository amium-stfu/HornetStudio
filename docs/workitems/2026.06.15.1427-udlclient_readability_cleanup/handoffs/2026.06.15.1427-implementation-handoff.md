# IMPLEMENTATION HANDOFF

## Goal
Improve `Amium.UdlClient` readability and maintainability by removing unnecessary definitions, reducing duplicated channel/function mapping logic, and making `UdlClient` easier for humans to follow without changing its intended behavior.

## Scope
Included:
- Structural cleanup inside `src/Amium.UdlClient/UdlClient.cs`
- Small supporting cleanup inside `src/Amium.UdlClient/Module.cs` if it directly improves readability
- Targeted tests for changed logic if test coverage exists or can be added with low scope

Explicitly not included:
- Protocol changes
- New features
- Broad architectural migration into multiple new services unless a very small extraction is clearly justified
- Plugin registration changes unless required by the cleanup

## Starting Point
- `UdlClient` currently mixes transport lifecycle, frame dispatching, module creation, write queue handling, resend/timeout behavior, and diagnostics in one class.
- Several helper methods are very small or unused and add indirection without carrying real complexity.
- Channel/function mapping is duplicated across multiple methods and should be unified to avoid drift.
- The user explicitly asked for a readability-focused review with no overengineering and no unnecessary wrappers or definitions.

## Tasks
1. Remove dead or low-value definitions in `UdlClient` that do not improve clarity, especially unused helpers and trivial pass-through wrappers.
2. Consolidate the channel/function/type mapping so the same relationship is defined once and reused consistently.
3. Reshape the frame-handling and pending-write flow into clearer local units while keeping behavior stable.
4. Review `Module` only for directly related simplifications; do not expand scope.
5. Validate the result with the smallest meaningful build/test pass for the touched area.

## File-Level Changes
- `src/Amium.UdlClient/UdlClient.cs` -> main readability cleanup, mapping consolidation, dead-code removal, smaller clearer internal flow
- `src/Amium.UdlClient/Module.cs` -> optional small cleanup only if it reduces duplication introduced by `UdlClient` changes
- Relevant test project files if needed -> cover changed mapping or writeback behavior

## Implementation Order
1. Identify all duplicated channel/function mappings and decide on one canonical internal representation.
2. Refactor `UdlClient` around that canonical mapping with minimal surface change.
3. Remove unused or trivial helper methods that no longer add value after the refactor.
4. Apply any strictly related cleanup in `Module`.
5. Run verification and fix any regressions introduced by the simplification.

## Technical Constraints
- Keep the existing project structure and naming conventions.
- Prefer minimal fragmentation; do not introduce new wrapper layers without a concrete benefit.
- Do not change behavior outside the readability/simplification scope.
- Keep chat-facing conclusions and implementation comments in German only when communicating in chat; code/comments stay English.
- Prefer named arguments where parameter meaning is otherwise unclear.

## Acceptance Criteria
- `UdlClient` is materially easier to read because duplicated mapping logic is centralized.
- Unused or purely cosmetic helper definitions are removed.
- No new abstraction layer is introduced unless it clearly removes duplication and remains local.
- Existing runtime behavior for frame handling and pending writes remains unchanged from the caller perspective.

## Verification
- Build the relevant solution or project using the repository’s normal .NET workflow.
- Run targeted tests if a suitable test project exists for `Amium.UdlClient` or adjacent behavior.
- If automated coverage is not available, perform a focused manual code-path review for frame dispatch, pending write queueing, timeout, and acknowledgment paths.

## Out of Scope
- Reworking the full runtime ownership model
- Introducing a new runtime service split
- Heartbeat feature expansion beyond cleanup of currently dead structure
- Documentation changes outside directly relevant structural notes

## Risks / Watchouts
- Mapping cleanup can accidentally change which channel corresponds to function/type values.
- Simplifying writeback flow can affect timing-sensitive acknowledgment behavior.
- Removing wrappers must not hide a subtle future extension point unless it is already used concretely.

## Relevant Files (if known)
- `src/Amium.UdlClient/UdlClient.cs`
- `src/Amium.UdlClient/Module.cs`
- `src/Amium.UdlClient/UdlClientPlugin.cs`

## Notes
- Favor local simplification over introducing new classes.
- If a split becomes necessary, keep it extremely small and internal to the same project.
