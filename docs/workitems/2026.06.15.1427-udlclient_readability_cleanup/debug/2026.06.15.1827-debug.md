# DEBUG REPORT

## Problem
Connecting a UDL hardware client still aborts the receive path with an item-path validation error.

## Expected Behavior
Incoming UDL frames should create or update runtime module items without terminating the receive loop.

## Actual Behavior
The receive loop exits after a path validation exception.

## Error Messages / Logs
- `[CanHub] rx loop error=ArgumentException: Item path segment 'm0A0' must use lowercase snake_case and start with a letter.`
- `[CanHub] rx loop exited`

## Relevant Code
- `src/Amium.UdlClient/UdlClient.cs` already formats module names in lowercase.
- `src/HornetStudio.Host/HostUdlClient.cs` still formatted module names with uppercase hex via `m{moduleId:X3}`.
- `Amium.Item/ItemPath.ValidateSegment(...)` accepts lowercase snake_case segments only.

## Attempted Fixes
- Lowercase module names in `src/Amium.UdlClient/UdlClient.cs` -> did not resolve the hardware runtime error.
- Root-cause check of log source -> log comes from `CanHub`, which is used by `HostUdlClient`, not the standalone `Amium.UdlClient`.
- Lowercase module names in `src/HornetStudio.Host/HostUdlClient.cs` -> expected to stop the `m0A0` path validation failure.

## Current Hypothesis (optional)
- The failing runtime path was built by `HostUdlClient`, so the previous fix in `Amium.UdlClient` could not affect the active hardware path.
