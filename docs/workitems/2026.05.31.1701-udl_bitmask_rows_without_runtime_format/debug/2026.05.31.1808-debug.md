# DEBUG REPORT

## Problem
Module-scoped UDL bit exposures in the browser/headless path show helper bits, but toggling `*.bits.bitN` does not write the underlying channel mask back. The `Read helper bits route to Set` option also appeared ineffective in practice.

## Expected Behavior
- Saving a route-only exposure definition must persist `RouteReadInputToSetRequest=true`.
- Toggling `studio.<folder>.<client>.m001.set.bits.bit1` to `true` should update the effective `set` write mask to `2`.
- Toggling `studio.<folder>.<client>.m001.read.bits.bit1` with `RouteReadInputToSetRequest=true` should update the effective `set` write mask to `2`.

## Actual Behavior
- Route-only persistence was reported as lost after reopening.
- Browser/headless bit items were created, but toggling them did not change the underlying `set` mask.

## Error Messages / Logs
- No dedicated runtime error was emitted for headless bit toggles.
- Existing code inspection showed browser/headless exposure projection had no writeback event handling, while the widget path already had `ApplyBitWriteback(...)`.

## Relevant Code
- `src/HornetStudio.Editor/UdlClients/UdlClientExposureProjection.cs`
- `src/HornetStudio.Editor/UdlClients/UdlClientRegistryProjection.cs`
- `src/HornetStudio.Editor/Widgets/UdlClient/UdlClientControl.axaml.cs`
- `src/HornetStudio.Editor/UdlClients/UdlClientDefinitionFileCodec.cs`

## Attempted Fixes
- Add focused route-only persistence coverage through the UDL client file codec.
- Add browser/headless writeback handling in `UdlClientRegistryProjection` for owned public bit paths.
- Reuse shared bit metadata and mask writeback logic in `UdlClientExposureProjection`.

## Current Hypothesis (optional)
- The observed "not saved" symptom for `Read helper bits route to Set` was likely dominated by missing headless/browser writeback, not by YAML serialization loss.
