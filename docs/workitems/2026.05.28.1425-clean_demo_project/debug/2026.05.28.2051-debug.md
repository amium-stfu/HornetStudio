# DEBUG REPORT

## Problem
Project startup still froze after the Controller fixes. Logs showed the same EnhancedSignal runtime being configured and added repeatedly:

`[EnhancedSignal:demo_enhanced_signal_1] configured folder=main source=udl_client_1.m001.read mode=Average filterTimeMs=5000`

followed by repeated registry adds for:

`studio.main.enhanced_signals.demo_enhanced_signal_1`

## Expected Behavior
An unchanged file-backed EnhancedSignal definition should create one runtime and keep it across repeated folder/runtime sync calls.

## Actual Behavior
The EnhancedSignal runtime was repeatedly disposed and recreated. Because `Dispose()` removes the registry root, every recreate logged a fresh `DataRegistry Added` event for the same key. During startup this could cascade into registry refreshes and UI unresponsiveness.

## Error Messages / Logs
Relevant user-provided log pattern:

- repeated `configured folder=main source=udl_client_1.m001.read`
- repeated `Added key=studio.main.enhanced_signals.demo_enhanced_signal_1`

Focused validation:

- `dotnet build src\HornetStudio.Host\HornetStudio.Host.csproj --no-restore` passed.
- `dotnet build src\HornetStudio.Editor\HornetStudio.Editor.csproj --no-restore` passed. One run had a transient retry warning from a locked `HornetStudio.Contracts.dll`, then succeeded.
- `dotnet build src\HornetStudio.Host.Tests\HornetStudio.Host.Tests.csproj --no-restore` passed.
- `dotnet src\HornetStudio.Host.Tests\bin\Debug\net9.0\HornetStudio.Host.Tests.dll` passed: `Host registry tests passed: 54`.

## Relevant Code
- `src/HornetStudio.Host/EnhancedSignalRuntimeManager.cs`
  - previously compared the incoming persisted definition to `existing.Definition`
  - now stores an immutable serialized definition key beside each runtime and compares against that key

- `src/HornetStudio.Host/EnhancedSignalRuntime.cs`
  - runtime definitions can change during runtime operations, for example adjustment writes or Kalman teach/apply behavior

- `src/HornetStudio.Host.Tests/Program.cs`
  - added regression coverage that mutating a runtime definition does not cause `EnhancedSignalRuntimeManager.SyncDefinitions(...)` to recreate the runtime when the persisted definition is unchanged

## Attempted Fixes
- Fix 1 -> Changed `EnhancedSignalRuntimeManager` to compare incoming definitions against the last synchronized persisted definition key instead of the mutable runtime definition. Result: Host and Editor builds pass, Host self-tests pass with new regression coverage.

## Current Hypothesis (optional)
- The startup freeze was caused by repeated EnhancedSignal runtime recreation. The repeated recreation was possible because runtime-owned mutations made `DefinitionsEqual(existing.Definition, definition)` unstable even when the persisted YAML did not change.
