# DEBUG REPORT

## Problem
File-backed computed custom signals were registered, but timer/source-based recomputation did not run without a placed `CustomSignals` widget.

## Expected Behavior
For `Folders/main/Signals/Custom/demo_custom_computed.yaml`, the formula `if({A}==true,10 ,0 )` should evaluate to `10` when `signals.custom.demo_custom_bool` is set to `true`. Because the trigger is `Timer` with `triggerIntervalSeconds: 1`, the value should refresh after the timer interval.

## Actual Behavior
`demo_custom_bool` changed to `true`, but `demo_custom_computed` stayed at `0`.

## Error Messages / Logs
No exception was required to reproduce the issue.

Focused validation:

- `dotnet build src\HornetStudio.Editor\HornetStudio.Editor.csproj --no-restore` passed with `0` warnings and `0` errors.
- `dotnet build src\HornetStudio.Editor.Tests\HornetStudio.Editor.Tests.csproj --no-restore` passed with `0` warnings and `0` errors.
- `dotnet src\HornetStudio.Editor.Tests\bin\Debug\net9.0-windows\HornetStudio.Editor.Tests.dll` timed out after 120 seconds without stdout/stderr. A 20-second redirected run also produced no stdout/stderr before being stopped.

## Relevant Code
- `src/HornetStudio.Editor/ViewModels/MainWindowViewModel.cs`
  - now subscribes to data registry item changes for central custom signal recomputation
  - owns a `System.Threading.Timer` for timer-triggered file-backed custom signals and posts evaluation to the UI dispatcher
  - preserves timer intervals and existing values when a timer-triggered computed signal is not due
  - ignores changes to computed custom signal output items to avoid self-triggered refresh loops

- `src/HornetStudio.Editor/Widgets/CustomSignals/CustomSignalsControl.axaml.cs`
  - still contains the widget-local evaluation path for visible controls, but folder-local resource files no longer depend on it.

## Attempted Fixes
- Fix 1 -> Added central registry-change and timer-driven recomputation in `MainWindowViewModel` for custom signal resources. Result: focused editor build succeeds.
- Fix 2 -> Replaced the first `DispatcherTimer` implementation with `System.Threading.Timer` to avoid keeping test/application lifetime tied to an Avalonia timer instance. Result: focused editor and editor-test builds succeed; the existing console test executable still times out without output and needs separate investigation if full test execution is required.

## Current Hypothesis (optional)
- The registration bug and this computed-signal bug had the same architectural cause: file-backed resources were moved out of `Folder.yaml`, but parts of their runtime behavior were still owned by optional widgets.
- The remaining behavior to verify manually is the live app path: setting `studio.main.signals.custom.demo_custom_bool` to `true` should update `studio.main.signals.custom.demo_custom_computed` to `10` after the configured timer interval.
