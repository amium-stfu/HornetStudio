# DEBUG REPORT

## Problem
Controller resources had several migration regressions after moving definitions into folder-local `Controllers/*.yaml` files:

- PID runtimes were published below `studio.<folder>.controller_widget.<name>`.
- The runtime published the process value as `source` instead of `read`.
- Browser add/edit/delete did not refresh folder runtime synchronization.
- Loading a project with active controller runtimes could freeze or become unresponsive.

## Expected Behavior
Folder-local controller runtimes should publish below `studio.<folder>.controller.<name>`, expose the resolved process value as `read`, start/stop through the direct value of `run`, and not trigger unrelated resource synchronization loops.

## Actual Behavior
The runtime path still used the old widget-owned naming. The process value appeared as `source`. The last CustomSignals fix also reacted to every data registry item change; a controller runtime publishing snapshots every compute interval caused repeated custom signal synchronization.

## Error Messages / Logs
Focused validation:

- `dotnet build src\HornetStudio.Host\HornetStudio.Host.csproj --no-restore` passed.
- `dotnet build src\HornetStudio.Editor\HornetStudio.Editor.csproj --no-restore` passed with one transient copy retry warning because `HornetStudio.Host.dll` was briefly locked.
- `dotnet build src\HornetStudio.Host.Tests\HornetStudio.Host.Tests.csproj --no-restore` passed.
- `dotnet src\HornetStudio.Host.Tests\bin\Debug\net9.0\HornetStudio.Host.Tests.dll` passed: `Host registry tests passed: 53`.
- `dotnet build src\HornetStudio.Editor.Tests\HornetStudio.Editor.Tests.csproj --no-restore` was blocked by running/debugged `HornetStudio` output DLL locks from `.NET Host (26760)` and `Microsoft .NET Core Debugger (31064)`.

## Relevant Code
- `src/HornetStudio.Host/PidControllerRuntime.cs`
  - runtime root changed to `studio.<folder>.controller.<name>`
  - process value child changed from `source` to `read`
  - runtime value extraction now prefers `Item.Value` before snapshot properties

- `src/HornetStudio.Editor/ViewModels/MainWindowViewModel.cs`
  - CustomSignal registry-change handling now only queues evaluation when the changed path matches a configured CustomSignal source path

- `src/HornetStudio.Editor/Widgets/Controller/ControllerControl.axaml.cs`
  - browser save/delete now refreshes folder bindings so file changes immediately synchronize runtimes

## Attempted Fixes
- Fix 1 -> Changed controller runtime path from `controller_widget` to `controller`. Result: Host and Editor builds succeed.
- Fix 2 -> Changed runtime process value child from `source` to `read`. Result: Host self-tests pass after expected path update.
- Fix 3 -> Narrowed CustomSignal registry-change handling to relevant configured source paths. Result: prevents controller snapshot updates from causing broad CustomSignal re-sync loops.
- Fix 4 -> Added folder binding refresh after controller browser save/delete. Result: file-backed controller edits are synchronized immediately.

## Current Hypothesis (optional)
- The project-load freeze was caused by high-frequency controller runtime snapshots triggering the overly broad CustomSignal central recomputation path.
- The remaining `controller_widget` text in `MainWindowViewModel` is the persisted canvas widget kind path segment, not the controller runtime root.
