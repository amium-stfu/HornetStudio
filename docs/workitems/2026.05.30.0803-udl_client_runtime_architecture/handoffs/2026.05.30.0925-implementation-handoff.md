# IMPLEMENTATION HANDOFF

## Goal
Instrument the remaining UDL startup responsiveness gap so the next benchmark identifies the UI-thread work that causes the current maximum delay. The goal is diagnosis, not a larger architecture change.

## Scope
Included:
- Add focused timing diagnostics for the gap between `PublishClientItems` and `SynchronizeAttachedItems`.
- Instrument local UI-thread sections in the existing UDL adapter control that may run after runtime items are updated.
- Add very small no-op guards only when the guard is obvious, local, and behavior-preserving.
- Preserve the current UDL runtime/browser migration direction.

Explicitly not included:
- Building the final UDL browser UI.
- Refactoring the UDL runtime architecture further.
- Optimizing `ProjectAttachedItems` before the remaining max-spike source is identified.
- Broad changes in `Monitor`, `EnhancedSignals`, `MainWindowViewModel`, or registry infrastructure.
- Changing persisted project format or release/version metadata.
