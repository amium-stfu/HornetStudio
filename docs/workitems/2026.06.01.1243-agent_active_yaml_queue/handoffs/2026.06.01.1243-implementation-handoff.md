# IMPLEMENTATION HANDOFF

## Goal
Replace the existing single active workitem pointer `docs/workitems/active.md` with a compact FIFO YAML queue at `docs/workitems/active.yaml`, and align the agent and Copilot instructions with the new `#done` completion command.

## Scope
- Update repository agent instructions for the new queue-based active workitem workflow.
- Add a `DONE` mode / `#done` command that removes the first queue entry after implementation is complete.
- Update `.github/copilot-instructions.md` so Copilot follows the same `active.yaml` queue rules.
- Replace current references to `docs/workitems/active.md` in current workflow documentation.
- Introduce `docs/workitems/active.yaml` as the single source of truth for active/planned implementation handoffs.
- Remove `docs/workitems/active.md` after the YAML queue is created.

Explicitly not included:
- Do not rewrite historical workitem handoffs under `docs/workitems/**`.
- Do not implement application runtime or UI code.
- Do not add status fields, summaries, timestamps, priorities, or history lists to `active.yaml`.
- Do not introduce external YAML tooling or dependencies.

## Starting Point
- `AGENTS.md` currently supports `#plan` and `#impl`, but not `#done`.
- `agents/planning.md` currently requires `PLAN` to overwrite `docs/workitems/active.md`.
- `agents/implementation.md` currently requires `IMPLEMENT` to read `docs/workitems/active.md`.
- `.github/copilot-instructions.md` currently tells Copilot to use `docs/workitems/active.md`.
- `docs/workitems/active.md` currently points to one active workitem and handoff.

Target queue shape:

```yaml
queue:
  - workitem: docs/workitems/2026.06.01.1243-agent_active_yaml_queue/
    handoff: docs/workitems/2026.06.01.1243-agent_active_yaml_queue/handoffs/2026.06.01.1243-implementation-handoff.md
```

Empty queue shape:

```yaml
queue: []
```

## Tasks
1. Add `DONE` mode routing to `AGENTS.md`.
2. Add a new `agents/done.md` workflow module for `#done`.
3. Update `agents/planning.md` from `active.md` overwrite behavior to `active.yaml` queue append behavior.
4. Update `agents/implementation.md` from `active.md` pointer reading to first-entry `active.yaml` queue reading.
5. Update `.github/copilot-instructions.md` with the same `active.yaml` / `#done` rules.
6. Create or update `docs/workitems/active.yaml`.
7. Remove `docs/workitems/active.md`.
8. Verify that current non-historical workflow instructions no longer point to `docs/workitems/active.md`.

## File-Level Changes
- `AGENTS.md` -> Add `#done` / `[MODE: DONE]` routing and module reference.
- `agents/done.md` -> New mode module defining completion behavior for the first queue entry.
- `agents/planning.md` -> Replace active pointer rules with FIFO queue append rules.
- `agents/implementation.md` -> Replace active pointer lookup with first queue entry lookup.
- `.github/copilot-instructions.md` -> Align Copilot with the YAML queue workflow and `#done`.
- `docs/workitems/active.yaml` -> New active queue file.
- `docs/workitems/active.md` -> Remove because it is superseded.

## Implementation Order
1. Update `AGENTS.md` mode list, short command list, and mode module list with `DONE`.
2. Create `agents/done.md` with concise, solution-neutral rules:
   - Read `docs/workitems/active.yaml`.
   - If `queue` is missing, malformed, or empty, stop and report that no active workitem exists.
   - Remove only the first queue entry.
   - Do not edit workitem history.
   - Do not implement code.
   - Keep the response short.
3. Update `agents/planning.md`:
   - Required active file becomes `docs/workitems/active.yaml`.
   - `PLAN` appends one queue entry after creating the handoff.
   - `PLAN` creates `active.yaml` with `queue: []` when missing.
   - `PLAN` must not overwrite or reorder existing queue entries.
   - The queue entry stores repository-relative `workitem` and `handoff` paths only.
4. Update `agents/implementation.md`:
   - `IMPLEMENT` reads `docs/workitems/active.yaml`.
   - `IMPLEMENT` uses exactly the first `queue` entry as the primary execution source.
   - `IMPLEMENT` does not remove queue entries.
   - If the file is missing, malformed, empty, or references missing paths, stop and ask for clarification.
5. Update `.github/copilot-instructions.md` to mirror the new rules:
   - Include `#done` in supported short mode commands.
   - Replace `active.md` references with `active.yaml`.
   - State that first `queue` entry is active.
   - State that `#done` removes the first queue entry.
6. Create `docs/workitems/active.yaml` and seed it with any currently active workitem from `docs/workitems/active.md` if it is still relevant.
7. Delete `docs/workitems/active.md`.
8. Run focused text checks and review the resulting docs.

## Technical Constraints
- Keep all agent module files solution-neutral except `agents/solution.md`.
- Do not add a YAML `version` field.
- Do not add `active`, `backlog`, `done`, `status`, `summary`, or `history` fields.
- Treat the queue as FIFO.
- Preserve repository-relative paths.
- Do not rewrite historical workitems or archived handoff text.
- Keep instruction wording concise and deterministic.

## Acceptance Criteria
- `AGENTS.md` recognizes `#done` as `[MODE: DONE]`.
- `agents/done.md` exists and defines the completion behavior.
- `#plan` rules append to `docs/workitems/active.yaml` instead of overwriting `active.md`.
- `#impl` rules read only the first `queue` entry from `docs/workitems/active.yaml`.
- `#done` rules remove only the first `queue` entry.
- `.github/copilot-instructions.md` no longer instructs Copilot to use `docs/workitems/active.md`.
- `docs/workitems/active.yaml` exists and contains only a top-level `queue`.
- `docs/workitems/active.md` is removed.
- Historical `docs/workitems/**` files are left unchanged.

## Verification

```powershell

```

- Confirm there are no current workflow references requiring `docs/workitems/active.md`.
- Confirm any remaining `active.md` matches are either absent or explicitly historical/deprecated.
- Confirm `docs/workitems/active.yaml` has only `queue`.
- No solution build is required because this change is documentation and agent workflow only.

## Out of Scope
- Application source code changes.
- Runtime behavior changes.
- New dependencies.
- Release versioning.
- Changelog updates unless the implementer decides this workflow change is relevant enough for project-facing documentation.

## Risks / Watchouts
- `#done` must be an exact mode token, not a loose alias, to avoid accidental command activation.
- Removing `active.md` is a workflow-breaking change for agents that have not read the updated instructions.
- `queue` means "planned or active until done"; there is no separate in-progress state.
- If multiple agents run concurrently, the first queue entry can be implemented twice unless humans coordinate. Do not add locking or status fields in this workitem.
