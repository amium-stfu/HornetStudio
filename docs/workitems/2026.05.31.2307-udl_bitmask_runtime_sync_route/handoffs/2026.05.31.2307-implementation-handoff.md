# IMPLEMENTATION HANDOFF

## Goal
Restore old `UdlClientControl` bitmask runtime parity in the file-backed/headless UDL architecture. Bit helper items must stay synchronized when numeric mask values change, bit writeback must update the correct channel, and `Read helper bits route to Set` must persist and behave correctly after reopening the dialog.

## Scope
Included:
- Fix headless UDL bit helper value synchronization when numeric mask values change.
- Fix or complete `RouteReadInputToSetRequest` save/load behavior in the module exposure dialog.
- Fix read-to-set routed behavior so `read.bits.bitN` follows the effective set target when configured and does not show stale/inverted values.
- Preserve old working `UdlClientControl` semantics.
- Add focused regression tests for numeric mask updates, bit writeback, route persistence, and route behavior.

Explicitly not included:
- New bitmask feature design.
- Full exposure dialog redesign.
- ItemClient support.
- Generic bitmask framework for non-UDL clients.
- Release/versioning work.

## Starting Point
- Bitmask rows now appear in `UDL Module Exposures`.
- User reports:
  - Setting `.set.bit0 = true` correctly sets the numeric value to `1`.
  - Setting the numeric value to `1` does not update `.set.bit0`; it stays `false`.
  - `Read helper bits route to Set` is not saved; reopening the dialog shows `false`.
  - Read-to-set behavior appears wrong/inverted:
    - `.set.bit0 -> true` then `.read.bit0 = false`
    - `.set.bit0 -> false` then `.read.bit0 = true`
- Old `UdlClientControl` behavior reportedly worked.
- Current headless projection is in `src/HornetStudio.Editor/UdlClients/UdlClientExposureProjection.cs`.
- Old widget implementation still contains reference behavior in `src/HornetStudio.Editor/Widgets/UdlClient/UdlClientControl.axaml.cs`.

## Tasks
1. Compare old widget and headless projection behavior.
   - Inspect old `OnExposureTargetChanged`, `ApplyBitWriteback`, `SetRuntimeExposureBitValue`, `ResolveExposureBitValueSourceValue`, and `ResolveExposureWriteTargetChannel`.
   - Compare with `UdlClientExposureProjection`.
   - Identify missing event/value update path in headless projection.
2. Add live bit value synchronization.
   - When a runtime channel's numeric mask source changes, update existing `bits.bitN` values.
   - This must work for `read`, `set`, and `alert` helper bits.
   - Do not rebuild the full structure for high-frequency value changes; update only affected bit item values.
   - Keep structure rebuilds for structural/config changes.
3. Fix direct numeric mask behavior.
   - Numeric `set` mask value `1` must set `set.bits.bit0 = true`.
   - Numeric `read` mask value `1` must set `read.bits.bit0 = true` when not routed.
   - Numeric `alert` mask value `1` must set `alert.bits.bit0 = true`.
4. Fix bit writeback consistency.
   - Setting `set.bits.bit0 = true` must update the set write mask and keep `set.bits.bit0` true.
   - Clearing it must update the mask and keep the bit false.
   - Avoid stale UI/registry state after writeback.
5. Fix read-to-set route persistence.
   - Ensure `ReadInputRouteToSetRequest` in the dialog writes `RouteReadInputToSetRequest=true` to the `read` exposure definition.
   - Ensure the definition is not filtered out during serialization just because other fields are default.
   - Ensure reopening the module exposure dialog restores the checkbox from the saved `read` definition.
6. Fix read-to-set route behavior.
   - With `RouteReadInputToSetRequest=true`, `read.bits` should use the effective set target source consistently.
   - Bit writeback from `read.bits.bitN` must write to set.
   - Displayed `read.bits.bitN` must update after writeback or numeric set-mask changes.
   - No inverted/stale behavior should remain.
7. Add focused tests.
   - Headless projection creates bit items and updates them from numeric source values.
   - Direct numeric mask updates update bits.
   - Bit writeback updates numeric mask and bit state.
   - Route checkbox save/reopen roundtrips.
   - Routed read bits follow set target values.
   - No `UdlClientControl` is required.
8. Add minimal diagnostics if useful.
   - Log or expose enough information to diagnose bit route/update issues without noisy high-frequency logs.

## Acceptance Criteria
- Setting numeric `set` mask to `1` updates `set.bits.bit0` to `true`.
- Setting numeric `set` mask back to `0` updates `set.bits.bit0` to `false`.
- Setting `set.bits.bit0 = true` updates the numeric set mask to `1` and leaves the bit true.
- `Read helper bits route to Set` stays checked after saving and reopening the exposure dialog.
- With read-to-set route enabled, `read.bits.bit0` follows the effective set target consistently and is not inverted/stale.
- Bitmask behavior works with no `UdlClientControl` widget in the folder.
- Tests cover numeric update, bit writeback, route persistence, and routed read behavior.

## Risks / Watchouts
- The current headless projection may only synchronize during structural refresh. Adding value sync must not trigger expensive rebuilds.
- Route-only `read` definitions can be easy to drop if serialization filters definitions without `ExposeBits`; preserve route state explicitly.
- Avoid writeback feedback loops when bit writes update numeric masks and numeric masks update bits.
- Preserve old path names and item metadata because existing bindings may depend on them.
