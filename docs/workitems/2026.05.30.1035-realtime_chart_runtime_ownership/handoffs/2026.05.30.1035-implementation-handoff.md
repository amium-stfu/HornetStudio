# IMPLEMENTATION HANDOFF

## Goal

Make a structural cut in the RealtimeChart implementation so chart runtime state, sampling, and history are no longer owned by the visual control instance.

The Realtime Chart must keep its history when switching folders/pages, avoid recurring UI lags from chart sampling, and leave the visual control responsible only for rendering snapshots and user interaction.

## Scope

Included:

- Move RealtimeChart history and sampling ownership out of `RealtimeChartControl`.
- Keep a stable runtime state per chart identity.
- Preserve chart history across folder/page/visual detach and reattach.
- Keep chart rendering in the existing Avalonia/ScottPlot control.
- Keep the existing persisted chart configuration model unless a small internal mapping is necessary.
- Add focused diagnostics for runtime attach/detach, sampling, and history retention.

Not included:

- Full UDL startup cleanup.
- UDL browser migration.
- Monitor runtime redesign.
- Replacing ScottPlot.
- Reworking the entire registry architecture.
- New dependencies.

## Starting Point

Current user-visible symptoms:

- Startup still has an extreme lag of roughly `5-10s`.
- Chart behavior is partially improved but still has recurring lags.
- Switching folders/pages can lose chart history.

Current structural issue:

- `RealtimeChartControl` still owns too much runtime behavior.
- The control creates or accesses runtime state, controls sampling lifecycle, renders data, and is tied to visual attach/detach.
- History is effectively coupled to UI/control/folder lifecycle instead of a stable chart runtime identity.

Relevant existing file:

- `src/HornetStudio.Editor/Widgets/RealtimeChart/RealtimeChartControl.axaml.cs`

Important project rule:

- Visual controls must not own long-running runtime lifecycles such as timers, sampling loops, or folder-wide runtime services.
- UI controls may observe runtime services and render snapshots, but the runtime service must be scoped independently from Avalonia controls.

## Tasks

1. Define the runtime ownership boundary.
2. Introduce a RealtimeChart runtime state/service scoped by stable chart identity.
3. Move history and sampling into the runtime state/service.
4. Convert `RealtimeChartControl` into a view over runtime snapshots.
5. Preserve history across folder/page/visual changes.
6. Verify lags and history behavior with the existing benchmark and manual folder switching.

## File-Level Changes

- `src/HornetStudio.Editor/Widgets/RealtimeChart/RealtimeChartControl.axaml.cs`
  - Remove long-running sampling ownership from the visual control.
  - Keep UI rendering, crosshair interaction, pause/clear commands, axis adjustment, and snapshot rendering.
  - Bind to a chart runtime state by stable identity.
  - Request snapshots from runtime state instead of holding authoritative history inside the control.
  - On detach, release only the visual subscription/owner, not the underlying chart history.

- `src/HornetStudio.Editor/Widgets/RealtimeChart/RealtimeChartRuntimeState.cs`
  - New focused class if it fits the current project structure.
  - Own chart history, series runtime bindings, sampling timer, non-reentrant sampling guard, and trimming.
  - Expose cheap immutable snapshots to the control.
  - Resolve chart series to runtime items outside the render path.

- `src/HornetStudio.Editor/Widgets/RealtimeChart/RealtimeChartRuntimeManager.cs`
  - New focused class if needed to manage states by chart identity.
  - Provide `GetOrCreate`, `AttachOwner`, `DetachOwner`, and cleanup behavior.
  - Scope state lifetime to stable chart identity and folder/project lifetime, not visual control lifetime.
  - Avoid orphan timers when charts are removed or no longer owned by an active folder/project.

- `src/HornetStudio.Editor/Monitoring/UiResponsivenessDiagnostics.cs`
  - Only adjust if existing timing labels no longer describe the new flow.
  - Keep benchmark comparison possible.

- `src/HornetStudio/docs/widgets/descriptions/*RealtimeChart*` and `src/HornetStudio/docs/widgets/help/*RealtimeChart*`
  - Update only if user-visible behavior or widget semantics change.

## Implementation Order

1. Inventory current responsibilities in `RealtimeChartControl.axaml.cs`.
   - Identify history storage, sampling timer, series config parsing, registry item resolution, snapshot generation, and UI rendering.

2. Extract runtime state.
   - Move history lists, series configuration/bindings, sample timer, sampling guard, trim logic, and value sampling into a runtime state class.
   - Keep methods small and aligned with existing naming/style.

3. Add runtime manager.
   - Manage runtime states by stable chart identity.
   - Identity should include enough context to avoid collisions, for example folder name plus chart item ID if item IDs are not globally unique.
   - Ensure visual detach does not delete history.

4. Rewire `RealtimeChartControl`.
   - On data context change, attach to the runtime state.
   - On visual detach, detach the view owner only.
   - Render immutable snapshots from the runtime state.
   - Keep control-level UI state such as crosshair and axis overrides in the control.

5. Define cleanup rules.
   - Stop sampling when no active owners need sampling.
   - Retain history across normal folder/page switches.
   - Release history when the owning folder/project/runtime is actually closed or when the chart item is removed.
   - If folder/project close hooks are not obvious, implement conservative owner-based stopping first and document cleanup follow-up.

6. Preserve commands.
   - Clear should clear runtime history for that chart identity.
   - Pause should pause the visual/control behavior and, if appropriate, owner sampling demand without destroying history.
   - Axis changes should remain visual-only.

7. Validate.
   - Build.
   - Run the same benchmark.
   - Switch folders/pages and verify history persists.

## Technical Constraints

- Use existing C#/.NET/Avalonia patterns already present in the project.
- Do not add dependencies.
- Code, comments, XML docs, UI text, and technical identifiers must be English.
- Keep chat/documentation concise and German-facing when responding to the user.
- Avoid broad refactoring outside RealtimeChart unless strictly necessary.
- Do not make UDL or Monitor changes in this workitem.
- Runtime code must not read Avalonia UI objects.
- Background diagnostics must not require UI-thread-only objects.

## Acceptance Criteria

- Switching away from a folder/page and back does not lose RealtimeChart history.
- RealtimeChart history is keyed by stable chart identity, not visual control instance.
- Detaching a visual control stops only the visual subscription/render timer, not the authoritative history.
- Chart sampling continues only when runtime ownership rules say it should, and it does not depend on Avalonia visual attach state.
- The chart still renders current and historical values correctly after reattach.
- `RealtimeChart.SampleCurrentValues.ResolveSamples` no longer appears as a frequent UI-lag hotpath.
- The benchmark does not regress chart render timing.
- No orphan chart timers remain after chart removal or application shutdown.

## Out of Scope

- Fixing the full `5-10s` startup lag.
- Optimizing `MonitorRuleRow` evaluation.
- UDL client browser migration.
- Changing persisted project file formats.
- General registry redesign.

## Risks / Watchouts

- If chart item IDs are not globally unique, runtime identity must include folder context.
- Keeping history across folder switches can leak memory if cleanup is missing. Add explicit cleanup or document a follow-up if folder/project disposal hooks are unclear.
- Runtime state must not capture `FolderItemModel` if that model is UI-thread-bound or short-lived. Prefer copying configuration into runtime-safe records.
- If sampled `ItemModel` access is not thread-safe, use existing registry-safe access patterns or a UI-independent value snapshot.
- Pausing the visual control must not accidentally delete runtime history.
