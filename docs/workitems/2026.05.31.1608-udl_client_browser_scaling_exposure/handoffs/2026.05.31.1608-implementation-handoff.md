# IMPLEMENTATION HANDOFF

## Goal
Finish the UDL client browser transition by removing the remaining `UdlClientControl` dependency from attached item editing and making the Received/Attached UI scale to many modules. The browser must edit file-backed UDL exposure/attach configuration and remain usable with 50+ received modules.

## Scope
Included:
- Replace the current `Edit` dependency on a matching `UdlClientControl` widget.
- Move UDL attached/exposure configuration into the file-backed client model under `Clients/Udl/<client-id>.yaml`, or an explicitly client-owned file if existing schema pressure proves that necessary.
- Keep `AttachedItemPaths` as a simple compatibility/input form where needed, but introduce a structured attach/exposure representation for browser edits.
- Make Runtime/Projection read the file-backed attach/exposure configuration without requiring a widget.
- Update the Clients Browser UDL detail body so Received and Attached lists scale to 50+ modules.
- Fix current browser layout defects:
  - duplicate `[Reload]`
  - inconsistent row button styles
  - incorrect `[Attach]` button state after `[Detach]`
  - Received and Attached panel content starting at different Y positions
- Add focused tests for file-backed attach/exposure editing and runtime/projection usage.

Explicitly not included:
- Reintroducing `UdlClientControl` as a required runtime or edit anchor.
- Full ItemClient browser implementation.
- Generic client provider framework beyond the current Clients Browser shell.
- UDL status/view widget.
- Release/versioning work.
- Large redesign of runtime/projection outside what is needed for file-backed attach/exposure configuration.

## Starting Point
- `ClientsBrowser` exists and lists UDL clients from `Clients/Udl/*.yaml`.
- Runtime/projection starts without UDL widgets.
- Layout issues remain in the UDL detail:
  - two `[Reload]` buttons are visible.
  - row buttons such as `[Edit]`, `[Detach]`, `[Attach]`, and disabled `[Attached]` do not consistently match theme/button styling.
  - after `[Detach]`, the corresponding `[Attach]` state can render incorrectly.
  - Received and Attached list content does not align vertically, likely because `[AddDemo]` changes header/action height.
- Biggest architectural problem: `Edit` currently works only when the current folder contains a matching `UdlClientControl` widget, because exposure configuration still lives or is resolved through that widget.
- Target architecture: UDL widgets can be removed completely from folders; browser and runtime must operate from `Clients/Udl/<client-id>.yaml`.
- Future scale: many received modules are expected, potentially more than 50.

## Tasks
1. Identify the current `Edit` dependency.
   - Locate where the Attached row `[Edit]` action searches for a `UdlClientControl` item.
   - Identify what configuration it reads/writes from the widget.
   - List the minimum configuration fields needed to preserve existing exposure behavior.
2. Define the file-backed attach/exposure model.
   - Prefer storing it in the existing client YAML if it remains readable.
   - Keep `AttachedItemPaths` for simple cases and compatibility.
   - Add structured configuration for edited items, for example:
     - attached path
     - text/label if needed
     - exposed channels
     - bit/channel settings
     - read/write exposure options
   - Runtime/Projection should prefer structured attach/exposure entries and fall back to `AttachedItemPaths`.
3. Update UDL definition codec/model.
   - Extend `UdlClientDefinition` and `UdlClientDefinitionFileCodec` for structured attached/exposure entries.
   - Preserve existing YAML load behavior.
   - Avoid duplicating client identity in YAML.
   - Keep field names English and stable.
4. Update runtime/projection consumption.
   - Ensure `UdlClientRuntimeManager` and projection logic read the file-backed structured attach/exposure configuration.
   - Remove the need to find a page-backed `UdlClientControl` for attach edit/projection.
   - Trigger projection refresh when attach/exposure config changes.
5. Replace Attached row `Edit`.
   - `Edit` opens a file-backed attached item/exposure dialog or editor.
   - Source: selected client's YAML definition.
   - Save writes back to `Clients/Udl/<client-id>.yaml`.
   - Save resyncs runtime/projection through the existing manager boundary.
   - No dependency on a `UdlClientControl` item.
6. Make lists scalable.
   - Use fixed-height panels with internal scrolling.
   - Add search/filter for Received and Attached if feasible in this step.
   - Keep stable row height and stable button positions.
   - Avoid rebuilding lists on high-frequency value updates; refresh only for structure/attach/filter/client changes.
7. Clarify bulk action semantics.
   - Replace or reinterpret `[All]` as `Attach all visible` if the UI text can fit.
   - If `[All]` remains, apply it only to filtered/visible rows or add confirmation for large counts.
   - Ensure it does not unexpectedly attach 50+ hidden modules.
8. Fix layout defects.
   - Remove duplicate `[Reload]`.
   - Use the same theme-compatible style/classes for all row action buttons.
   - Disabled `[Attached]` must look intentionally disabled, not broken.
   - Ensure `[Detach]` recomputes Received row state so it returns to `[Attach]`.
   - Give Received and Attached panel headers/action rows the same reserved height even when `[AddDemo]` is hidden.
9. Add tests.
   - Loading old `AttachedItemPaths` still works.
   - Saving/editing structured attach/exposure config roundtrips.
   - Runtime/projection does not require `UdlClientControl` for edited exposure config.
   - Detach updates file-backed config and received/attached state correctly.
10. Update documentation.
   - Document file-backed attached/exposure configuration.
   - Clarify that `UdlClientControl` is no longer required for edit/projection.
   - Update Clients Browser behavior if user-visible labels/actions change.

## Implementation Order
1. Trace current `[Edit]` flow from Attached row to widget lookup.
2. Inventory the exact exposure configuration currently stored on or derived from `UdlClientControl`.
3. Add file-backed structured attach/exposure model with backward-compatible `AttachedItemPaths` fallback.
4. Add codec tests for old and new YAML forms.
5. Update projection/runtime to consume file-backed config.
6. Replace browser `[Edit]` with file-backed edit dialog/action.
7. Fix `[Attach]`/`[Detach]` state transitions against the file-backed model.
8. Fix row button styles and duplicate reload.
9. Add list scaling UI:
   - fixed scroll areas,
   - stable header/action row height,
   - optional filters/search.
10. Update docs and samples if needed.
11. Run tests/build and manually verify with 50+ module scenario if feasible.

## Technical Constraints
- Chat responses must be German.
- Code, comments, XML documentation, UI text, file names, and technical identifiers must be English.
- Public classes and public methods require XML documentation.
- Use existing Avalonia/theme button styles; do not create one-off button visuals.
- Browser is a visualization/editor over `./Clients`; it is not runtime/projection owner.
- Runtime/projection must work without `UdlClientControl` widgets.
- Registry event handling must be scoped and filtered before UI dispatch.
- Avoid list rebuilds for high-frequency value changes.
- Keep the schema readable; do not split into extra files unless same-file YAML becomes clearly unwieldy.
- Avoid overengineering a generic attach/exposure framework for other client types in this step.

## Acceptance Criteria
- Attached item `[Edit]` works without any `UdlClientControl` widget in the folder.
- Exposure/attach edit data is persisted under the file-backed UDL client configuration.
- Runtime/projection consumes edited configuration after save.
- `AttachedItemPaths` simple definitions still load.
- Received and Attached panels stay aligned vertically.
- Only one `[Reload]` action is visible.
- `[Attach]`, disabled `[Attached]`, `[Edit]`, and `[Detach]` use consistent theme-compatible button styling.
- After `[Detach]`, the Received row returns to a correct `[Attach]` state and the Attached row is removed.
- Browser remains usable with at least 50 received modules.
- Browser close/open does not affect runtime/projection lifetime.

## Verification
- Focused tests for:
  - legacy `AttachedItemPaths` load,
  - structured attach/exposure roundtrip,
  - widget-independent edit/projection,
  - detach state update.
- `dotnet build HornetStudio.sln --no-restore`.
- Manual verification:
  - Remove UDL widgets from the demo/debug folder.
  - Open `ClientsBrowser`.
  - Confirm `Edit` on an attached item opens and saves configuration without widget dependency.
  - Attach and detach a received item and verify button states.
  - Verify `Received` and `Attached` panels align.
  - Verify only one reload button exists.
  - Test with a demo setup containing 50+ modules or generated received rows and confirm scrolling/filtering remains usable.

## Out of Scope
- Full ItemClient detail implementation.
- Generic exposure framework for all client types.
- UDL browser visual redesign beyond the listed layout fixes and scaling needs.
- Rewriting the runtime.
- Release/versioning.

## Risks / Watchouts
- Existing projection code may still silently fall back to widget data; remove or clearly isolate this path.
- Saving structured config must not drop simple existing `AttachedItemPaths` unexpectedly unless migration is deliberate.
- Large YAML files can become hard to read if every channel is expanded by default; only persist explicit non-default exposure choices where practical.
- Bulk attach actions can surprise users when many modules are filtered out or hidden; scope `[All]` carefully.
- Disabled buttons can be visually too subtle in the current theme; verify contrast and state clarity.
