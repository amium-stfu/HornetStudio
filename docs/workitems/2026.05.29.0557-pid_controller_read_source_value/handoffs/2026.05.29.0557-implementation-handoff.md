# IMPLEMENTATION HANDOFF

## Goal
Ensure a PID controller runtime publishes the current source measurement on its `read` item even when the controller is not running.

## Scope
Included:
- Adjust PID controller runtime input synchronization so `controller.<name>.read` reflects the configured `sourcePath` independently of `run`.
- Keep PID output computation and output writes gated by `run=true`.
- Add focused test coverage for stopped-controller source read behavior.

Not included:
- No new controller types.
- No PID tuning changes.
- No changes to EnhancedSignal runtime behavior unless a direct defect is found while verifying the PID read path.
- No UI redesign.

## Starting Point
- `samples/HornetStudioReference/Folders/main/Controllers/pid_1.yaml` uses `sourcePath: enhanced_signals.enhanced_signal_1.read`.
- The source exists and is published by `EnhancedSignalRuntime` under `studio.<folder>.enhanced_signals.<name>.read`.
- `PidControllerRuntime` resolves the source through `EnhancedSignalPathHelper.EnumerateResolutionCandidates(...)`.
- Current observed behavior: `controller.pid_1.read` remains empty or `false` while `run=false`, although the source exists.
- Likely cause: source resolution is performed inside `EvaluateController()`, and runtime evaluation is timer-driven after `run=true`.

## Tasks
1. Inspect `PidControllerRuntime` initialization, registry event handling, timer lifecycle, and snapshot publication.
2. Separate input synchronization from PID output computation inside `PidControllerRuntime`.
3. Make source and setpoint state refresh happen during initialization and when relevant source or setpoint registry items change.
4. Keep `run=false` behavior from writing outputs while still publishing the latest readable source value.
5. Add or update focused host/runtime tests for stopped PID read synchronization.
6. Run focused verification and a solution build when feasible.

## File-Level Changes
- `src/HornetStudio.Host/PidControllerRuntime.cs` -> introduce or extract input refresh logic; keep output computation behind `run`.
- `src/HornetStudio.Host.Tests/Program.cs` -> add focused self-test coverage for a stopped PID runtime reading an available source.
- `src/HornetStudio/docs/widgets/ControllerWidget.md` -> update only if the documented behavior currently implies `read` is updated only while running.
- `src/HornetStudio/docs/widgets/help/ControllerWidget.help.md` -> update only if the help text describes stale or run-gated read behavior.

## Implementation Order
1. Add a failing focused host test that creates a source item, creates a PID runtime with `run=false`, and asserts `CurrentSourceValue` plus published `read` mirror the source.
2. Extract PID input synchronization from `EvaluateController()` into a small private method, for example `RefreshInputState()`.
3. Call the input refresh during construction before or during the initial snapshot publication.
4. In `OnRegistryItemChanged`, filter for source candidate changes and refresh input state without triggering output writes.
5. Update `EvaluateController()` so it uses the refreshed values and returns early for `run=false` after publishing state.
6. Add a second assertion that changing the source while stopped updates `controller.<name>.read`.
7. Verify output writes still only occur while `run=true`.

## Technical Constraints
- Keep the change local to the existing runtime architecture.
- Do not add new services, wrappers, or dependencies.
- Use existing `EnhancedSignalPathHelper` candidate resolution and path comparison helpers.
- Registry event handlers must filter by owned runtime paths or configured source/output paths before acting.
- User-visible runtime state and alert strings must remain English.
- Keep XML documentation current for any new public API; prefer private methods for this change.

## Acceptance Criteria
- A stopped PID controller with a valid numeric source publishes that value on `controller.<name>.read`.
- Source changes update the controller `read` value while `run=false`.
- PID output computation and output target writes do not occur while `run=false`.
- Existing running PID behavior remains intact.
- Source path resolution still works for folder-relative paths such as `enhanced_signals.enhanced_signal_1.read`.

## Verification
- `dotnet build HornetStudio.sln --no-restore`
- Focused host test execution according to repository convention: run the built `src/HornetStudio.Host.Tests` executable DLL directly with `dotnet <path-to-dll>`.
- Manual sample check: load `samples/HornetStudioReference`, inspect `controller.pid_1.read`, and confirm it mirrors `enhanced_signals.enhanced_signal_1.read` before `run` is enabled.

## Out of Scope
- Changing sample PID tuning parameters.
- Changing UDL demo module behavior.
- Migrating controller YAML schema.
- Broad registry or browser-control refactoring.

## Risks / Watchouts
- Avoid reacting to unrelated global registry changes; only configured source/setpoint/runtime paths should trigger refresh.
- Avoid recursive `ItemChanged` loops when publishing snapshots.
- Avoid starting the PID timer just to keep `read` current.
- Preserve the distinction between source read publication and output control.
