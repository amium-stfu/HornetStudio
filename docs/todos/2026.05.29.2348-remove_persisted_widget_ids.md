# TODO

## Title
Remove persisted widget instance IDs from folder YAML.

## Problem
Folder YAML currently persists `Identity.Id` values for controls and widgets. File-based folder copies can therefore keep duplicate instance IDs even though the folder-local `Path` values are intentionally relative and copyable.

## Impact
Duplicate persisted IDs can make copied folders share UI or runtime state, for example RealtimeChart history keyed by `FolderItemModel.Id`. This weakens the intended folder-copy workflow where customers can copy a folder on disk and start HornetStudio.

## Suggested Fix
Treat folder-qualified paths as the persistent identity and make widget IDs transient. Stop writing `Identity.Id` to folder YAML, keep loading legacy IDs only for compatibility if needed, and change any runtime state keyed by `Id` to use a stable folder-qualified path key such as `FolderName + Path`.

## Priority
Medium
